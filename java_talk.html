JavaScript vs Java — Quick Comparison

Functions, collections, annotations, exceptions, and functional-style operations.

1) Functions / Methods with Error Handling

JavaScript

// function with throw
function add(a, b) {
  if (typeof a !== 'number' || typeof b !== 'number') {
    throw new Error('Args must be numbers');
  }
  return a + b;
}

// arrow function with throw
const divide = (a, b) => {
  if (b === 0) throw new Error('Division by zero');
  return a / b;
};

Java

// method with throws declaration
public class MathUtil {
  public static int add(int a, int b) throws IllegalArgumentException {
    if (a < 0 || b < 0) {
      throw new IllegalArgumentException("Args must be positive");
    }
    return a + b;
  }

  public static double divide(double a, double b) throws ArithmeticException {
    if (b == 0) throw new ArithmeticException("Cannot divide by zero");
    return a / b;
  }
}

JS throws without declaration; Java uses throws clause to signal checked exceptions.

2) Exception Handling (try-catch)

JavaScript

try {
  const result = add(5, 'text');
} catch (error) {
  console.error(error.message);
} finally {
  console.log('Operation done');
}

// catching multiple error types
try {
  risky();
} catch (e) {
  if (e instanceof TypeError) {
    console.log('Type error');
  } else if (e instanceof RangeError) {
    console.log('Range error');
  }
}

Java

try {
  int result = add(5, -3);
} catch (IllegalArgumentException e) {
  System.err.println(e.getMessage());
} finally {
  System.out.println("Operation done");
}

// multi-catch (Java 7+)
try {
  riskyMethod();
} catch (IOException | SQLException e) {
  e.printStackTrace();
}

JS has no checked exceptions; catch is type-agnostic. Java enforces exception declaration and catching by type.

3) Arrays, Objects, Map vs Java Collections

JavaScript

// Array
const arr = [1,2,3];

// Object (key-value)
const obj = { id: 1, name: 'Alice' };

// Map (ordered key-value)
const map = new Map();
map.set('a', 1);
map.set('b', 2);

Java

// List (ArrayList)
List list = new ArrayList<>(Arrays.asList(1,2,3));

// POJO (object)
class Person { 
  int id; 
  String name; 
  /* getters/setters */ 
}

// Map
Map map = new LinkedHashMap<>();
map.put("a",1);

JS objects are dynamic; Java collections are typed/generic and backed by concrete implementations (ArrayList, LinkedList, HashMap, LinkedHashMap, etc.).

4) Angular Decorators vs Spring Annotations

Angular (TypeScript)

import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-user',
  template: '
{{name}}
'
})
export class UserComponent {
  @Input() name!: string;
}

Spring (Java)

import org.springframework.stereotype.Service;
import org.springframework.beans.factory.annotation.Autowired;

@Service
public class UserService {
  @Autowired
  private UserRepository repo;
}

Both are metadata/decorator systems: Angular decorators are TS functions that augment classes; Spring annotations are Java annotations processed by the framework at runtime/compile.

5) Streams & Lambdas (Java) vs JS Array methods

Java (Streams + Lambdas)

List nums = Arrays.asList(1,2,3,4,5);
int sum = nums.stream()
              .filter(n -> n % 2 == 1)
              .mapToInt(Integer::intValue)
              .sum();

JavaScript (Array methods)

const nums = [1,2,3,4,5];
const sum = nums
  .filter(n => n % 2 === 1)
  .reduce((acc, n) => acc + n, 0);

Both support declarative pipelines. Java streams are lazy and parallelizable; JS array methods are eager (though libraries like RxJS exist).

Summary

  • Functions: JS is flexible and dynamic; Java requires explicit signatures and throws clauses.
  • Exceptions: Java enforces checked exceptions; JS relies on convention and try-catch.
  • Collections: JS objects/Maps are dynamic; Java collections are typed and generic.
  • Annotations: Both use decorators/annotations for metadata; execution models differ.
  • Functional style: Available in both; semantics and performance model differ.
